# PoC-рация для ОС Аврора — этап 1

Учебный каркас Push-to-Talk через IP-сеть: QML/Silica, C++17, qmake,
состояния `IDLE / LISTENING / TRANSMITTING`, локальная симуляция и TCP-клиент
для учебного сервера. **Звук на этом этапе не записывается и не передаётся.**

Архитектура, правила эфира и жизненный цикл подробно описаны в
[ARCHITECTURE.md](ARCHITECTURE.md).

## Важно: путь к проекту

Официальная инструкция Авроры требует, чтобы путь к проекту **не содержал
пробелов и кириллицы**. Поэтому исходное расположение
`D:\Vso chto ugodno\poc-radio` непригодно для штатной сборки в Aurora IDE.

На этом компьютере рабочая область SDK настроена как `C:\Users\kiege`,
поэтому самый простой рабочий вариант:

```text
C:\Users\kiege\projects\poc-radio
```

Можно использовать `D:\projects\poc-radio`, но только после добавления этого
каталога в общие рабочие области в настройках Aurora SDK. Проект должен
находиться в домашней директории пользователя или в разрешённой общей
директории SDK. После перемещения удалите старый каталог `build` и файл
`*.pro.user`, затем заново откройте проект.

Источник: [Создание нового проекта](https://developer.auroraos.ru/doc/5.2.1/sdk/app_development/work/create/create_new_project).

## Запуск в Aurora IDE 5.2.1

1. Перенесите проект в безопасный путь, как указано выше.
2. В Aurora IDE выберите **Файл → Открыть файл или проект…** и откройте
   `poc-radio.pro`.
3. В селекторе комплектов выберите **AuroraOS-x86_64**, конфигурацию **Отладка**
   и способ **Развернуть, используя RPM-пакет**.
4. Запустите Build Engine, если он не запустился автоматически при сборке.
5. Нажмите **Собрать**, затем запустите эмулятор и кнопку **Запустить**.
   Для отладки C++ используйте **Начать отладку**.
6. Для QML-отладки включите **Проекты → Сборка → Отладка и профилирование QML**.

Официальные инструкции: [сборка](https://developer.auroraos.ru/doc/5.2.1/sdk/app_development/work/build)
и [запуск/отладка на эмуляторе](https://developer.auroraos.ru/doc/5.2.1/sdk/app_development/work/launch).

### Если сборка зависает до вызова qmake

На этом компьютере причиной была остановленная среда Docker. В PowerShell:

```powershell
Start-Service com.docker.service
Start-Process 'C:\Program Files\Docker\Docker\Docker Desktop.exe'
docker version
```

Дождитесь появления в выводе `docker version` не только Client, но и Server.
Затем запустите Build Engine в Aurora IDE и повторите сборку. Если `sfdk`
сообщает «Команду необходимо использовать в рабочей области Аврора SDK»,
перенесите проект внутрь `C:\Users\kiege` либо измените разрешённые рабочие
области в настройках SDK. Официальная инструкция также предупреждает, что
не запущенный Docker может привести к бесконечному ожиданию сборки.

Для реального устройства позднее выбирается комплект `armv7hl` или `aarch64`
в соответствии с архитектурой устройства, а не `x86_64`.

## Проверка без сервера

По умолчанию включена **Локальная симуляция**:

1. Нажмите **Войти в канал** — появится `LISTENING`.
2. Удерживайте круглую **PTT** — появится `TRANSMITTING` после локального grant.
3. Отпустите кнопку — состояние вернётся в `LISTENING`.
4. Нажмите **Имитировать входящую передачу** — PTT заблокируется, потому что
   другой участник занял эфир.
5. Сверните приложение во время своей передачи — передача завершится,
   на обложке останется `LISTENING`.
6. **Выйти из канала** вернёт приложение в `IDLE`.

`AudioController` лишь отмечает включение/выключение тракта в журнале.
Это точки подключения будущих микрофона, Opus, UDP и воспроизведения.

## Проверка с учебным TCP-сервером

На компьютере в терминале:

```powershell
python tests\mock_server.py 5000
```

В приложении:

1. Выключите **Локальную симуляцию**.
2. Укажите адрес компьютера и порт `5000`.
   Для эмулятора предустановлен типичный адрес хоста `10.0.2.2`; если соединения
   нет, проверьте сетевой режим эмулятора и фактический адрес хоста.
   Для реального телефона укажите LAN-адрес компьютера, а не `127.0.0.1`.
3. Разрешите входящий TCP-порт 5000 в брандмауэре компьютера только для своей
   доверенной учебной сети.
4. Войдите в один канал с двух экземпляров/устройств под разными именами.
   Имя канала указывайте без пробелов; повторное имя участника сервер отклонит
   ошибкой `NAME_TAKEN`, потому что в простом протоколе `SPEAKER` пока нет ID.

Протокол: одна UTF-8 строка = одно сообщение.

| Клиент → сервер | Сервер → клиент | Смысл |
|---|---|---|
| `JOIN <канал> <имя>` | `ACK JOINED` | Вход в канал |
| `PTT_START` | `ACK PTT_GRANTED` / `ERROR BUSY <имя>` | Запрос эфира |
| `JOIN <канал> <имя>` | `ERROR NAME_TAKEN <имя>` | Имя уже занято в канале |
| `PTT_STOP` | `SPEAKER` | Освобождение эфира |
| `LEAVE` | `ACK LEFT` | Выход |
| — | `SPEAKER <имя>` / `SPEAKER` | Начало/конец передачи |
| — | `USERS <список>` | Участники |

Сервер учебный: без TLS, аутентификации, шифрования и передачи аудио.
Не используйте его как готовое решение для публичной мобильной сети.

## Что уже учтено, а что осталось

- Есть: полноценный шаблон Aurora Qt Quick, разделение C++/QML, состояния,
  серверный grant, правило одного говорящего, сворачивание, KeepAlive,
  DisplayBlanking, иконки, RPM-метаданные и Qt-тесты.
- Пока нет: реального звука, Opus/UDP, сервера для интернета, авторизации,
  гарантированного приёма в замороженном фоне и постоянного хранения настроек.

Следующий технический этап — сначала проверить аудиотракт отдельно в симуляции,
затем на реальном устройстве и только после этого объединить его с PTT-логикой.
